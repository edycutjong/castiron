# DEVIATIONS — spec vs reality

Design specs are fixed up front. Every forced deviation gets a row here (newest
first). Frictions with upstream value also land in `docs/friction-log.md`.

| Date | Spec ref | What changed | Why | Impact / follow-up |
|---|---|---|---|---|
| 2026-07-04 | ARCHITECTURE "Run metadata: SQLite (**SQLModel**)" | **DB layer built on stdlib `sqlite3`, not `sqlmodel`.** | This build sandbox has **no network** (PyPI DNS fails); `sqlmodel`/`sqlalchemy`/`aiosqlite` are not installed and not in the uv cache, so `uv add sqlmodel` cannot resolve. | `castiron/db.py` implements the **identical** run/stage/event schema behind a thin `Database` repository + row dataclasses — always-green, zero-dep OFFLINE. SQLModel swap is mechanical behind this surface once a networked `uv sync` is possible. Not a capability gap. |
| 2026-07-04 | BUILD_PLAN P1 "UI rail fills live (Next.js scaffold)" | **Rail shipped as a static HTML+EventSource page (`web/console.html`, served at `GET /console`), not a Next.js app.** | Same offline constraint: `npx create-next-app` / `npm install` need the npm registry (unreachable). The offline fallback plan sanctions this ("ship a static HTML+EventSource stage-rail page … the SSE contract is what matters, not the framework"). | Full SSE contract proven live (curl + browser): rail fills from `GET /runs/{id}/events`, shows the ladder rung + fallback. Next.js scaffold deferred to a networked session (P8 polish); the page's EventSource logic ports directly to `app/page.tsx`. |
| 2026-07-04 | SDK_COVERAGE ✅ "CLI verify/extract/index/replay"; P0 exit test | **No `genblaze` CLI ships** in 0.4.1 (no console-script / `__main__` / cli module). | Empirically absent; verify/extract exist only as Python handler methods. | P0 verify done via `Manifest.verify()` + `get_handler(mime).verify(path)`. Ship `castiron verify` CLI at P6. Dossier F-01. |
| 2026-07-04 | ARCHITECTURE "Mock/Failing/ModelError providers" | **No `FailingProvider`/`ModelErrorProvider` classes.** | `genblaze_core.testing` ships only Mock* providers; failure is `MockProvider(should_fail=True, error_code=…)`. | Added `castiron.providers.failing_provider()` shim. Dossier F-02. |
| 2026-07-04 | COMPLEXITY §3 / invariant I5 "`CostLedger`" | **No `CostLedger` class.** | Grep = 0 hits. Real surface: `step.cost_usd`, `AgentResult.total_cost_usd`, event `total_cost_usd`. | Cost meter + single-charge invariant sum `step.cost_usd`. Capability present; spec name only. Friction F-03. |
| 2026-07-04 | ARCHITECTURE "in-file manifests" via ObjectStorageSink | **Sink writes run-level `manifest.json`; it does NOT embed in-file.** | In-file embed is a separate `SmartEmbedder`/handler pass. | Publish step embeds the read-back manifest into `episode.mp3`. Friction F-06. |
| 2026-07-04 | (new dep) | **Added `mutagen>=1.47`** to core deps. | MP3 ID3 embedding needs it; without it embed silently degrades to a `.genblaze.json` sidecar and `Mp3Handler.verify()` raises. Chose `mutagen` directly over the heavy credentialed `[audio]` extra. | Episodes get true in-file ID3 manifests in OFFLINE + CI. Friction F-04. |
| 2026-07-04 | COMPLEXITY §2 "tamper demo = re-encoded MP3 fails verify" | **`Manifest.verify()` checks provenance hash, not audio payload.** | Documented: it does not re-hash `asset.url` bytes. Catches manifest edits, not audio re-encode. | Manifest-tamper red-path works now; audio-payload authenticity check (payload re-hash) added at P4. Dossier F-05. |
| 2026-07-05 | SDK_COVERAGE #7 | `webhooks.SIGNATURE_HEADER` set to `x-bz-event-notification-signature` (B2-docs shape, not yet confirmed) | The delivered-signature header name is platform-side and needs a live B2 rule to confirm; build sandbox has no live B2 | LIVE P3: confirm exact header, change the one constant. Verifier logic (HMAC-SHA256 over raw body) is correct regardless. |
| 2026-07-05 | P3 scope | P3 built as credential-independent core (webhook receiver + stage machine + publish) against SYNTHETIC B2 events, ahead of live verification | Build sandbox has no live B2 credentials; kept momentum on the credential-free core | P3 not DONE until live keys verify real Event Notifications + real Object Lock enforcement. Offline tests become the regression net. |
| 2026-07-05 | ARCHITECTURE (backend) | pipeline.py + app/main.py hardcode `LocalDirBackend`; no OFFLINE→LIVE backend factory yet | P0–P3 were credential-free by mandate; live backend deferred to P3-live | P3-live: add a `make_backend(settings)` factory returning `S3StorageBackend.for_backblaze(...)` when creds present, `LocalDirBackend` otherwise. `scripts/live_smoke.py` already proves the live backend works standalone. |
